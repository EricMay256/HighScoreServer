## What shipped

Six rounds of external review landed on PR #14 before it merged. Every finding was
confirmed; none was rejected. The ones worth carrying forward as *habits* rather than
history:

- **Never raise the MCP SDK's `AuthorizeError` or `TokenError` inside a transaction
  block.** They are frozen dataclasses, so contextlib's exit path raises
  `FrozenInstanceError` instead — and anything the block did rolls back. This was hit
  three times in three methods, because none of those branches is reachable without two
  concurrent requests. `tests/vault/test_boundaries.py` now enforces it lexically.
- **An unverified name is not an identity.** The consent screen led with `client_name`
  from an open registration endpoint; the OAuth principal was derived from it too. Both
  fixed, and the second was found only because the first prompted a look.
- **Docs are load-bearing.** `AGENTS.md` told a maintainer to preserve the exact login
  ordering that a later fix had to reverse. Standing guidance that describes a state the
  system has left is worse than none.

Then, after the merge: the wiki import ran against production, `Agent/wiki/` joined
`CORPUS_OWNED_PATH_PREFIXES`, the Stage-A compile loop retired, and every script that
writes to a live database now prints which one before acting.

## Open work, in the order I would take it

### 1. Merge `dev` into `main` on both repos

Both are docs-and-hardening commits with no migration and nothing to deploy.
HighScoreServer `dev` has `22f9d77` (NEXT-STEPS correction) and `d923da6` (the
`VAULT_PUBLIC_URL` drift check plus runbook updates). knowledge-platform `dev` has the
compile retirement and its spec.

**Watch out:** the knowledge-platform pre-push hook enforces an AI write policy by
diffing `ai-claude/*` branches against `origin/master`. Because `dev` is ahead of
`master` on seven governance files, any AI-named branch cut from `dev` is blamed for
edits it never made. Pushing `dev` itself is unaffected. Worth fixing the hook to diff
against the merge base.

### 2. Run the exporter against the live Vault

`Agent/wiki/` is owned now, so `--apply --prune` will finally sweep it. Measured, not
guessed, by exporting production into a scratch directory and diffing:

- All 15 wiki files reproduce. **33 real differing lines**: 28 are the 14 `CompileRunID`s
  moving from Stage-A run keys to uuids, 5 are the regenerated index.
- Another ~1500 diff lines are **CRLF vs the LF the exporter writes deliberately**.
- **61 of 70 notes differ**, almost entirely in their `ID` line — Stage-A wrote those
  files with its own ids. A first `--apply` rewrites them.
- Prune would delete exactly one file: `Agent/wiki/_frontier.yml`, a Stage-A artifact
  whose content is now `vault_compile_runs.output_frontier` and which planning no longer
  reads at all.

None of that is data loss, but it is a large and alarming-looking diff in the vault repo.
Dry-run into a scratch directory first. Running it also clears the `wiki-index-stale`
warning `check-wiki` currently reports, which is the live confirmation that the
cross-repo index-blurb fix was right.

### 3. Nothing can compile until a credential exists

No credential holds `vault:compile`. When one is issued, **expect the first plan to offer
every uncovered active note** — that is migration `0015` working as intended, surfacing
what the frontier had been suppressing, including anything the flagged-then-approved bug
had stranded permanently.

### 4. Optional: finish enabling OAuth

`VAULT_PUBLIC_URL` and `VAULT_OPERATOR_PASSWORD_HASH` are both set in production. What has
not happened is an end-to-end test of the flow. The full procedure is in
`app/vault/docs/vault-configuration.md` under "Turning the OAuth authorization server on",
including the discovery checks for **both** `…/mcp` and `…/mcp/` — RFC 9728 derives the
metadata path from the resource path, so they are two different documents and serving one
is a 404 for whichever half a client was configured with.

**Use `curl.exe`, never bare `curl`.** In PowerShell `curl` is an `Invoke-WebRequest`
alias that shares none of curl's flags; a mis-parse leaves it *prompting* for a parameter,
and a prompt looks like an invitation to paste. That is how an operator password hash got
echoed to the terminal today. The runbook now documents this.

### 5. Deferred, with the reasoning written down

- **Making the compile plan binding** — persisted work items, an Alembic revision, an
  explicit "declined" state. Recorded in ADR 0027's amendment as deferred rather than
  dismissed, with the cost named: a buggy compiler that writes nothing and finishes
  advances the frontier past notes it never covered.
- **A two-tier public release** — `engine/specs/two-tier-compile-restoration.md` in
  knowledge-platform. The mechanical restore is one commit revert; the interesting part is
  four decisions a revert gets silently wrong, chiefly that the index blurb becomes a
  cross-*tier* contract and that the two tiers no longer plan the same way.
- **Moving `app/vault/` to its own repository** — the actual enabler for the two-tier
  story, and already half-prepared: own `AGENTS.md`, own ADRs, own Alembic lineage, and a
  boundary test that fails on any `from app.` import.

## Conventions this session kept having to relearn

- **Verify against the system, not from memory.** Half the wasted time came from
  reasoning about state instead of querying it. `heroku releases:output <v>` settled an
  argument that no amount of inference would have.
- **`alembic current` needs `-c alembic-vault.ini`.** Without it you get the leaderboard
  lineage, which stops at `0004` — a plausible wrong answer.
- **`heroku pg:psql` is broken on this Windows install.** The psycopg one-liner in the
  runbook goes around it.
- **Falsify every regression test against the unfixed code before believing it.** Several
  tests this session passed for the wrong reason until checked that way, and one passed
  vacuously because the SDK refused before reaching the code under test.
